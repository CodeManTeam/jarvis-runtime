## 维护边界

### 当前维护

| 路径 | 角色 | 状态 |
| --- | --- | --- |
| `app/` | FastAPI、事件运行时、AI 编排、任务、记忆、设备协议 | 主线 |
| `watch-client/` | 展讯 8521 手表客户端 | 主线，真机到手后联调 |
| `console/` | 浏览器中控台 | 配套维护 |
| `tests/` | 后端、协议和运行时测试 | 主线 |
| `docs/` | 产品、协议、架构和验收文档 | 主线 |
| `deploy/` | 服务部署配置 | 主线，改动需单独验收 |

### 废弃或暂存

| 路径 | 处理方式 |
| --- | --- |
| ~~`watch/`~~ | 已移除（历史保存在 `backup/full-history` 分支） |
| `watch-client/app/build/` | Gradle 生成物，不作为源码维护 |
| `watch-client/.gradle/` | Gradle 缓存，不作为源码维护 |
| `jarvis-deploy.zip` | 打包产物，不作为源码维护 |
| `__pycache__/`、`.pytest_cache/` | 本地缓存，不作为源码维护 |

## 当前第一条产品闭环

```text
手表输入
  -> Event
  -> 门控/编排
  -> Activity
  -> Task / Memory / PendingAction
  -> WebSocket 或 HTTP 返回手表
  -> 活动详情和后续操作
```

开工顺序：

1. 统一 `Activity` API 和读取模型。
2. 手表客户端用 Activity 替代本地两条历史文本。
3. 重做 360×480 首页和详情页。
4. 拆分手表运行时与页面代码。
5. 真机 ADB 验证录音、摄像头、后台、功耗和网络。

## 生成物规则

源码、文档和测试进入版本控制；APK、ZIP、Gradle 缓存、Python 缓存和本地数据库不进入版本控制。
清理动作必须先确认目标路径，不用清理命令误删用户数据或已有未提交改动。

现有仓库已经跟踪部分 Gradle 缓存和 APK；`.gitignore` 不会取消既有跟踪。
本轮没有删除文件、修改暂存区或重置用户改动；移除历史生成物跟踪需单独整理。
`data/` 和 `.env` 是运行数据，不属于可清理生成物。
`A 4 Questions.txt` 是用户问答原始资料，保留原位；当前需求以 REQUIREMENTS_BASELINE.md 为准。
`structure.py` 是早期结构设计参考，不替代 app/ 实际运行实现。
