# Jarvis 产品定义与范围

版本：v0.2  
日期：2026-10-03

## 1. 产品定位

以 [需求基线](REQUIREMENTS_BASELINE.md) 为准。以下补充覆盖旧版冲突项，均为目标需求而非已实现声明。

Jarvis 的整体目标是秘书、第二大脑和行动助理；个人服务器、手表入口、未来多端，当前为个人自用，不按比赛作品规划。
默认持续语音感知，端侧声音阈值切段，服务端 ASR 和门控；门控聚合筛选后才调用 Agent。
自动短期记忆、周期长期总结、习惯识别和周期提醒建议是核心能力，而不是附属页面。
态势由 AI 感知，暂不设计课堂提问或谈判专门流程；普通活动不震动，紧急轻震。
低风险无需确认；对外社交发送需明确授权，财产风险及代码调整需确认。
普通记忆、人设和偏好调整不因为“自我迭代”而逐次确认。
手表有摄像头，由手表扫配置码；用户可修改存储上限，全量销毁暂不在当前范围。
模型每日预算 5000 万 Token；ASR 独立计时，每日不超过 5 小时。
持续监听不等于全天 ASR：声音阈值分段后才提交识别，达到 ASR 上限不得继续提交；文字输入仍可用。
不做开机自启、被杀自动复活、离线智能、多用户和水平扩展。
远程设备执行、AI 自修改、升级回滚属于后续受控能力，非当前既有能力或任意执行授权。
5 秒首反馈是待细化指标；不能承诺断网断电零漏提醒。
可解释性展示判断摘要、依据及工具轨迹，不是完整模型内部思维链。

Jarvis 是一个以手表为主要入口的个人环境感知助理。

手表负责：

- 采集语音和设备事件。
- 展示实时识别、AI 判断、提醒和活动日志。
- 接收服务端推送。
- 震动和执行受白名单限制的本地动作。

服务端负责：

- 事件标准化和去重。
- AI 理解、分类、记忆、任务规划和执行。
- 权限、风险、确认和撤销。
- 活动流、审计、任务和记忆持久化。

中控台负责：

- 查看完整活动。
- 管理任务、记忆、项目、设备和规则。
- 调试和审计。

## 2. 核心用户体验

Jarvis 不应该像一个持续打断用户的聊天机器人，而应该像一个安静的个人运行时：

1. 默认观察。
2. 识别有意义的信息。
3. 只有在有价值时才介入。
4. 需要用户决策时提供清晰动作。
5. 所有动作可追踪、可解释；分别标注可撤销、可补偿或不可逆。

## 3. 核心对象

```text
Event          外部或用户输入
Decision       AI 对 Event 的判断
Activity       面向用户的统一活动事实
PendingAction  等待用户确认的操作
Task           需要调度或执行的工作
Memory         长期上下文
AuditRecord    系统内部可追溯记录
Device         手表或其他接入设备
```

## 4. 端到端主流程

```text
手表采集
  -> Event
  -> 标准化/去重/忽略
  -> AI Decision
  -> Policy
  -> Activity
  -> Task / Memory / PendingAction / Reply
  -> WebSocket 推送
  -> 手表展示、震动或等待用户操作
```

## 5. 行为原则

- 低风险、低打扰优先。
- AI 可以高权限工作，但必须有策略边界。
- “接受”不是简单关闭弹窗，而是确认一项可追踪操作。
- “暂不”不新增噪声日志，而是在原活动上改变状态。
- 事件内容、AI 判断、最终结果不能混为一句不可解释的文本。
- 用户应能从一条日志回到原事件、任务和操作结果。

## 6. 版本范围

### 当前阶段

- 手表主界面和二级页面。
- 语音采集和实时识别状态。
- 服务端推送和活动流。
- AI 对话、记忆、提醒和确认动作。
- 通知、日历和位置事件。
- 扫码/手动配置。
- 前台服务、重连、有限缓存和紧急轻震；离线无智能能力。

### 暂不承诺

- 任意 Android 应用自动操作。
- 无确认的高风险外部通信。
- 本地离线大模型。
- 多用户协作。
- 医疗、金融和安全关键场景。
