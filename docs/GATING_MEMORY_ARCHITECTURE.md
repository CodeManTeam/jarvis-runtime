# 门控、记忆与行动架构

日期：2026-10-03；状态：目标设计，尚未完整实现。
需求来源：[需求基线](REQUIREMENTS_BASELINE.md)。不引入额外分布式基础设施。

## 主链路

```text
watch audio segments / text / notification / calendar / on-demand location
 -> raw asset reference + Event
 -> ASR (when needed)
 -> input gate: normalize, retain, aggregate, prioritize
 -> God Agent: context + retrieval + plan
 -> policy check -> tools / domain agents
 -> task result + memory changes + activity revision
 -> interruption gate -> screen / audio / light vibration

periodic consolidation:
 working memory + completed activity references
 -> evidence-linked long-term memories / habit hypotheses / cleanup candidates
```

## 门控不是每一层再调一次大模型

端侧声音阈值只减少无声传输，不能决定语义；服务端先做格式、重复和短窗口聚合。
只有需要语义时才调用模型；门控和主 Agent 可共享结构化结果，避免重复付费理解同一段话。
原始 ASR 和清洁文本分开，去噪不擅自改人名、时间和否定词；不确定信息保留标记。
记录每段输入的调用数、输入/输出 Token、缓存命中、费用估计及延迟。
同一原始资料重处理必须说明新增目的，预算耗尽延迟后台总结，不假装完成前台任务。
已确认预算：模型每日 50,000,000 Token；ASR 独立计时每日最多 18,000 秒。
以下为实现建议，尚未实现：按用户时区 Asia/Shanghai 自然日记账，
汇总门控、主 Agent、记忆整理、重试和降级的模型用量，不因换模型而重置额度。
输入、输出、缓存用量分别记录；供应商计量口径差异保留，不把 Token 上限等同于金额上限。
ASR 按实际提交识别的音频时长记账，而非麦克风开启时长；重复提交和重试也计入。
提交前预留时长，完成后核对，并发不能绕过上限；累计音频反复用于部分识别时也应计入重复提交。
达到上限停止新的 ASR 提交，显示额度状态并保留文字输入，不静默用另一条付费音频路径绕过限制。
持续监听与语音可识别状态分开显示；额度耗尽后的本地监听策略待实现时明确，不能承诺仍能理解语音。
聚合窗口、分段长度和门控阈值待实测。TTS 配额未指定，不套用 ASR 时长上限。
态势由 AI 感知，不加入课堂提问/谈判专项规则或人工模式选择要求。

## God Agent 与领域能力

God Agent 是编排职责，不是可绕过权限的超级账号。建议先复用已有任务/设备/日历/通知/位置能力。
另补记忆维护、检索和总结职责，先不为了命名拆出大量独立 Agent。
Agent 可互相委托，但设调用深度、总时限、预算和循环检测，继承而不能扩大调用者权限。
人工插话默认提交同一运行的补充事件；门控判断继续、改计划或安全点暂停。
明确“停止”必须立即进入停止流程，不交由模型自行决定是否服从；
不可中断工具标注等待安全点，不声称已经终止。

## 记忆层次

| 层 | 内容与使用 |
| --- | --- |
| 原始资料 | 音频/图片/原文及哈希、时间、来源；按需回溯，不默认全部进上下文 |
| 工作记忆 | 当前对话、关联事项、短期意图；直接进入预算内上下文 |
| 长期记忆 | 稳定偏好、习惯、人设、已确认事实；选相关部分注入上下文 |
| 活动与审计 | 发生过什么、版本变更和工具执行；检索后引用，不整库注入 |

记忆字段建议包含来源引用、置信度、有效时间、版本、固定标记和取代关系。
相反证据先标记冲突，不无声覆盖；一次行为不自动升级为长期偏好。
事件/活动与项目多对多关联，项目是可选视图，而非用户必须管理的目录。

## 海马体整理与删除

仅处理新增或变更资料，按预算定期总结；不把全量音频反复送进模型。
未完成任务、未决歧义、用户固定资料的来源暂不进入自动清理候选。
用户可修改存储上限；清理先生成清单：理由、引用关系、影响、恢复窗口；默认容量、满额行为与期限待设计。
原始资料已删除时返回“资料已清理”，不能以摘要冒充原始证据；不足时询问用户。
习惯假设保留观察次数/时间范围/反例；周期提醒需用户接受，避免重复推荐已拒绝事项。
全量销毁按用户最新要求暂缓，未来由 AI 协助，不进入当前开发和验收。
此延期不取消日常门控清理和用户管理记忆功能。

## 模型路由与降级

按 ASR、语义门控、规划/工具、视觉/视频、TTS 声明能力，逐端点验证。
GLM5.3 Flash 是用户提出的候选，不作为已验证供应商契约。
降级不能把缺失视频理解变成“已看懂”，不能用无工具能力模型伪造执行结果。
切换时保留 event_id/run_id，写操作按幂等键确认结果再重试，避免跨模型重复执行。
有限重试后，给出失败事实和人工可选择的下一步，不无限消耗 Token。

## 高权限与自我修改

低风险读取、整理、可恢复待办修改默认自动；社交发送需明确授权；
财产影响和代码调整需确认。用户已明确自我迭代指代码，普通偏好/人设/记忆调整不因此逐项确认。
上述澄清不允许 AI 自行扩大原有授权或绕过社交发送边界。
设备远程执行仅针对本人授权设备，通过认证、能力声明、运行时限制、审计及中止入口提供。
不存在不鉴权的公网任意命令接口。权限提升由人批准，不能由 God Agent 修改自己的审批规则。
升级建议采用版本工件、校验、健康检查、已知良好版本回滚；数据库迁移必须考虑备份兼容。
代码回滚不等于撤销已经发送的外部消息或已执行的财产动作。

## 解释与个人使用

UI 展示判断摘要、证据引用、计划步骤、工具参数/结果、耗时及修订记录。
不承诺提供模型内部完整私有思维链；不可用字段标记缺失。
原始模型调用日志需按访问权限查看，密钥/认证头不落日志。
个人自用，不再规划比赛材料或演示交付。未来如开源，发布内容另行确认，不附个人数据库和密钥。
