# 交付渠道（Delivery Channels）

- 状态：**设计**，配合 [CAPABILITY_FRAMEWORK.md](CAPABILITY_FRAMEWORK.md) 的 `produces` / `delivery`
- 要解决的问题：产出物做出来之后，**怎么真正到用户手里**，以及 agent 如何就交付方式与用户商量

---

## 1. 硬约束（来自设备现实）

| 约束 | 后果 |
| --- | --- |
| 手表屏 360×480、无键盘 | 不能把手表当交付终端，只能当"通知 + 摘要 + 短码" |
| 自有域名 + nginx + 证书（本项目用 `PUBLIC_BASE_URL` 配置） | 静态文件可直出，**这是最省事的交付通道** |
| 单用户、无多端同步 | 不需要分享链接权限体系 |
| 外发（邮件/微信）不可逆 | 必须走 `per_action` 许可 |

## 2. 通道分级

| 通道 | 现状 | 适用 | 成本 |
| --- | --- | --- | --- |
| `link` 静态链接 | ✅ 已有（`/files/...`） | 任何产出物 | 零 |
| `shortcode` 短码 | 待做 | 手表上给 4 位码，中控输入打开 | 小 |
| `console` 中控清单 | ✅ 已有（`/api/artifacts`） | 浏览器端下载 | 零 |
| `attach` 邮件/微信 | ❌ 无 | 需要发出去 | 每通道要许可 + 实现 |
| `handoff_page` 交接页 | 待做 | 把多个产物+说明做成一个页面 | 小（复用 web_page 能力） |

**默认谈的顺序**：`shortcode`（手表场景）→ `link`（手机/电脑）→ `console`（电脑）→ `attach`（需要许可）。

## 3. 短码设计

```
artifact.short_code   4 位 Base32（去掉易混字符 0/O/1/I）
显示      手表卡片里："PPT 已生成 · 码 K7QM"
打开      中控顶栏输入框输入 K7QM → 跳到 /api/artifacts?id=...
有效期    不过期（产物本来就有生命周期），但短码可回收（删除产物时一并失效）
```

理由：手表打不出长链接，念一串 URL 也不现实；4 位码是"从手腕到电脑"的最小摩擦。

## 4. agent 怎么谈交付

**不要**问"你要怎么接收？"这种开放问题。给具体选项 + 代价：

```text
已生成《周三会议》PPT，6 页，820KB。
- 短码 K7QM（手表现在就能看到，到中控输入即可打开）
- 直接链接 <url>
- 需要我发到邮箱/微信吗？那需要你单独许可一次，且发出去不能撤回
```

规则：

1. **只在产出成功后**谈交付，不在开工前问一堆。
2. 每条通道必须真实存在；不存在就明说"目前没有 X 通道"。
3. 涉及外发时，同时说清"不可撤回"。
4. 用户选了通道就**立刻执行**，不要再确认一遍（许可流程已经承担了确认）。

## 5. 与权限的关系

| 动作 | 能力 | 默认档 |
| --- | --- | --- |
| 生成产物 | `artifact.create` | `auto` |
| 读短码 / 列表 | 无（只读接口） | — |
| 邮件/微信外发 | `message.send` | `per_action`（锁定） |
| 生成交接页 | `artifact.create` | `auto` |

## 6. 一个明确的边界

用户问过"要不要写个 web 客户端传文件"。当前能做的与不能做的：

- **能**：生成静态页面并托管（展示、下载列表、说明页）。
- **不能**：接收上传（没有后端鉴权与存储）、登录、表单提交。
- 如果将来要"传文件给 Jarvis"，那是**入站**通道，需要新的能力包
  （`artifact.receive` + 体积上限 + 病毒/类型校验），不在本设计范围。

**任何情况下，agent 不得声称已经实现入站接收。**

## 7. 验收

1. 产出成功后，回复里**至少包含一种**真实可用的交付通道。
2. 短码能被 `/api/artifacts?code=...` 解析，且与产物一一对应。
3. 声称外发通道时，必须已配置；未配置则明确说没有。
