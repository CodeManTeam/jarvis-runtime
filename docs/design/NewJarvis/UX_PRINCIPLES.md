# UX 原则：消除"不稳、不确定、慢、不明确"

- 状态：**实施中**
- 用户原话：不要给用户"不稳定 不确定 速度慢 延迟高 不明确 不知道在干什么"的感觉
- 这份文档把感受翻译成**可验收的行为**

---

## 1. 六条硬规则

### R1 · 首屏不闪

"先显示空状态、再填数据"会被读成**出错**。加载中只能显示**骨架**（与真实结构同形），
不能显示"暂无数据"。空状态只在**确认没有数据之后**出现。

### R2 · 每个动作立刻有回应（< 100ms）

| 动作 | 立刻要发生的事 |
| --- | --- |
| 点「开始」建任务 | 卡片以 `已提交` 出现（不等网络） |
| 点「批准」 | 按钮进入忙碌态，状态变 `正在启动` |
| 点「取消」 | 按钮忙碌，状态变 `正在停止` |
| 保存配置 | 按钮忙碌 + 行内"保存中" |

**按钮忙碌态必须禁用**，避免双击产生重复任务。

### R3 · 等待必须有边界感

- 运行中的任务显示**已运行时长**（`已运行 1 分 20 秒`），每秒走字；
- 步骤流显示**最近一步在做什么**，而不是只有一个转圈；
- 超过 30 秒没有新步骤，显示`这一步比较慢，仍在进行`（不撒谎、不假装完成）。

### R4 · 状态词只有一个来源、一种语言

| 内部 | 展示 |
| --- | --- |
| `queued` | 待批准 |
| `running` | 进行中 |
| `done` | 已完成 |
| `failed` | 失败 |
| `cancelled` | 已取消 |

- 禁止把英文枚举直接展示给用户（当前 bug：胶囊写着 `queued`/`running`）；
- 同一个状态在任何页面用**同一个词**。

### R5 · 连接状态永远可见，且说实话

| 实况 | 展示 |
| --- | --- |
| 已连上 | 不显示（不打扰） |
| 断开重连中 | 顶部细条：`实时连接断开，正在重连（第 2 次）· 数据可能滞后 12 秒` |
| 重连成功 | 细条消失，**不弹 toast**（避免噪音） |

"数据可能滞后 N 秒"来自最后一次成功更新的时间，不是编的。

### R6 · 失败必须可行动

失败卡上除了原因，必须有**下一步**：`重试` / `查看日志` / `复制错误`。
没有下一步的失败就是死胡同。

## 2. 中控具体改动

1. 首批加载显示**骨架卡片**，不显示"暂无"；
2. 状态胶囊中文化（见 R4）；
3. 任务卡显示 `已运行 1 分 20 秒`，失败时显示**失败于第几步**；
4. 批准/取消按钮忙碌态；
5. 顶部连接细条（R5）；
6. 保存配置/新建任务的 toast 改为**行内确认**（toast 容易被忽略，且堆叠时很吵）；
7. 交付物空状态措辞：`还没有交付物` → `任务完成后的文件会出现在这里`（说明"这里会有什么"，不是"这里没有东西"）。

## 3. 手表具体改动

1. 说完话**立刻**显示 `已收到 · 处理中 0s`，每秒走字——用户最怕的是"说完没反应"；
2. 结果到达后替换为结果文本（不是追加一行小字）；
3. 失败时显示 `没成功 + 原因` 并提供 `重试`；
4. 超过 20 秒无响应：`还在处理，可以先放下`（降低焦虑，不撒谎）；
5. 转写常驻 + `重看` / `朗读`（已实现，保持）；
6. **不做**：任何自动跳屏、任何无操作 3 秒后的弹窗。

## 4. 验收

1. `pytest` 全绿；`node --check console/app.js` 通过；手表 `assembleDebug` 通过。
2. 中控：首屏骨架 → 数据；无英文状态词；按钮有忙碌态；连接细条文案含"滞后 N 秒"。
3. 手表：`speech_final` 后 100ms 内出现"已收到·处理中"，计时可见。
4. 视觉：不引入新色值；折叠/骨架沿用现有 token。

## 5. 不做

- 不做骨架动画循环（静态灰块即可，省电）
- 不做 toast 队列
- 不做"预计剩余时间"（我们没有可靠的估算，编一个就是撒谎）

## 6. 第二轮审查的处置记录

审查方（只读、不改代码）提出 15 条，处置如下，便于以后复查"为什么没做某条"。

### 采纳（14 条）

| 条目 | 处置 |
| --- | --- |
| 销毁按钮无忙碌态（P0） | 已改：禁用 + `销毁中…` + 不可重入锁 |
| 权限矩阵单选无即时反馈 | 已改：行级 `生效中…` |
| 回复发送按钮无忙碌态 | 已改，防重复发送 |
| `queued` 不参与轮询 | 已改：`running \|\| queued` |
| 失败任务"重试中…"文案错位 | 已改 |
| 步骤未到达时无提示 | 已改：`读取步骤中…` |
| 断线横幅误用 warn 黄 | 已改：中性色（语义色不再混用） |
| "未接入"与"没数据"视觉相同 | 已改：新增 `unbuiltPlaceholder()` |
| 设备离线缺相对时间 | 已改：`（12 小时前）` |
| `waiting-pill` 整块铺语义色 | 已改：点 + 描边 |
| 历史记录显示 `job.run_shell` | 已改：映射为中文动作名 |
| 手表 20 秒后秒数消失 | 已改：`还在处理（已 N 秒）` |
| 手表失败时多阶段同时高亮 | 已改：只标失败段 |
| 许可处理完主屏要等 5 秒 | 已改：回调里主动 `fetchActivities` |

### 否决（1 条，需再次确认）

| 条目 | 理由 |
| --- | --- |
| 点击感知区域触发语音 | 与"长按说话"的手势语义冲突；在没有真机验证前改手势，风险大于收益。保留现状，等真机确认后再议。 |

### 部分采纳（1 条）

审查建议**删掉四阶段指示条**（占 16+ 节点之一）。改为**收敛为只显示当前阶段的一行**（32dp 高），
而不是删除——因为"我正在哪一步"是消除不确定感的关键信息，删了会重新变成黑箱。
