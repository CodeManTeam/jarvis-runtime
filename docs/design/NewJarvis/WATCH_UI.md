# 手表 UI 规格（9 屏）

- 状态：**草案**，取代 [UI_LAYOUT_PLAN.md](../../UI_LAYOUT_PLAN.md)
- 设计稿：400×540（含 40 圆角设备框）；实机 360×480，换算规则见
  [DESIGN_SYSTEM_V2.md](DESIGN_SYSTEM_V2.md) §5
- 文案与坐标：逐帧原文见 [figma/texts.md](figma/texts.md)

## 总则

1. **每一屏只回答一个问题**。屏内不出现两个同等重要的决定。
2. **顶栏永远三段式**：左=时间，中=当前状态，右=电量。状态词是唯一的"现在发生了什么"。
3. **页面自身不含设置入口**。配置全部移入二级设置页，首页不再常驻"远端服务器配置"卡。
4. **所有状态色来自 [DESIGN_SYSTEM_V2.md](DESIGN_SYSTEM_V2.md) §2.3**，不新增颜色。
5. **不可逆提示必须出现在按钮之上**，且与按钮同屏。

## 屏间关系

```text
安静待机 ──抬腕/上滑──▶ 注意力流
注意力流 ──"为什么 ›"──▶ 四层依据
注意力流 ──高风险卡──▶ 高风险许可
注意力流 ──建议卡──▶ 习惯建议
任意屏 ──状态异常──▶ 服务降级 / 离线缓存
电量 ≤15% ──▶ 低电量极暗（覆盖任何屏的视觉层）
长按首页 ──▶ 语音输入
```

## 2. 有意义注意力流 · `8:9742`

**目的**：一屏看完"值得你注意的事"，四类语义互斥。

**顶栏**：`09:41` · `等待你 · 1`（琥珀）· `68%`
**标题行**：`值得你注意`（17，500）· 右 `脱敏演示`

四张卡的顺序与语义固定：

| 序 | 胶囊 | 标题示例 | 动作行 | 左竖条色 |
| --- | --- | --- | --- | --- |
| 1 | `高风险 · 等你` | 北岸提案已备好，尚未外发 | `审阅并许可 →` | 红 |
| 2 | `自动 · 已处理` | 已添加 14:30 提案复核提醒 | `低风险 · 撤销` | 绿 |
| 3 | `建议 · 确认一次` | 建议将复核提前 10 分钟 | `查看建议 →` | 琥珀 |
| 4 | `已忽略 · AI 已知情` | 午间简报不再提醒 | `查看留痕 →` | 无（弱色） |

每张卡右上角固定 `为什么 ›`，进入四层依据。

**底部**：`上滑看更多 · 下拉刷新 · 最近同步 09:41`

**规则**：
- 卡片按 `attention` 分类排序（高风险 > 建议 > 自动 > 忽略），同类按时间倒序。
- "自动·已处理"必须同时给出可撤销动作；不可撤销的自动动作不允许出现在这个位置。
- "已忽略"只能由用户操作或明确规则产生，AI 不得单方面隐藏。
- 卡片超过 6 张时截断，底部文案改为"上滑看更多（还有 N 条）"。

**数据**：`GET /api/activities?view=attention`（见 [ACTIVITY_EVIDENCE.md](ACTIVITY_EVIDENCE.md)）。

**顶栏**：`09:41` · `未发送 · 每次确认`（红）· `68%`
**标题**：`外发前，需要你许可`
**胶囊**：`● 高风险 / 外发消息`

**草稿卡**（`surface-raised`）：

```

“北岸提案 v3 已备好，请于 15:00 前查收。”

```

**不可逆声明**（正文色，不是弱色）：
`确认后将外发。送达后无法保证撤回；只能追加更正，并记录补偿操作。`

**依据行**：`置信度 96% · 记忆 2 · 工具 3 为什么 ›` + `草稿与收件人已核对，仍需你决定`

- 本屏不可被系统手势误触关闭；必须显式选择取消。
- 超时失效后回到注意力流，卡片标注 `许可已过期`。

**数据**：`grant` 对象（scope/expires_at/single_use/compensation_only），见 [PERMISSION_MODEL.md](PERMISSION_MODEL.md)。

## 5. 语音输入 · `8:9814`

**目的**：按住即说，松开即提交，全程可见"现在到哪一步了"。

**顶栏**：`09:37` · `正在听 · 仅按住时` · `68%`
**标题**：`触摸长按说话`

| 区 | 内容 |
| --- | --- |
| 波形区 | 5 根竖条动画 + 实时转录 `把北岸提案发给 林工，先让我看…` |
| 提示 | `流式转录 · 松开后提交 · 滑出取消` |
| 流水线 | `正在听 → 判断中 → 执行中 → 完成`（当前段高亮） |
| 说明 | `外发会转为「等待许可」，不会直接发送。首响应目标 ≤ 5 秒，非实测结果。` |
| 按钮 | `按住说话`（主）｜`改用文本`（次） |
| 页脚 | `屏上触摸操作 · 扬声器默认静音` |

**规则**：
- 松手前不发起任何工具调用；识别文本实时显示，允许边说边修正。
- 滑出即取消，不产生事件。
- 涉及外发/支付/设备的意图，**必须**落到许可屏，不允许语音"确认"直接执行。
- `≤5 秒`必须标注"目标/非实测"，实机测出数据后再改写。

### 端点检测：自动跟随环境

用户明确否决了"固定档位"和"滑动平均当底噪"两种做法。实现采用：

| 机制 | 做法 | 为什么 |
| --- | --- | --- |
| 底噪估计 | 最近约 40 秒能量的 **20 分位**，每约 1 秒刷新 | 人声占窗口远不到 80%，不会把底噪抬上去（均值法的致命伤） |
| 说话判定 | **起始阈值高、持续阈值低**（迟滞） | 一句话不会被一次换气切成碎片 |
| 适配方向 | 变吵**立刻**生效，变安静**缓慢**（每次刷新最多降 15%） | 喊完之后的那段静默不能把门打开、收进后面的噪声 |
| 用户控制 | 仅"更灵敏 / 标准 / 更保守"微调，缩放**整个边距** | 均匀噪声下微调也必须有效（只缩放扩散项会让它在稳态噪声里失效） |

- 静音依然不出设备；700ms 预录保留。
- 尾部静音的最后 55% 作为**宽限期**上报界面，显示「即将提交 N 秒（继续说话会接上）」，
  默认耐心 2200ms。
- 算法被抽成 `AdaptiveGate`（纯 JVM 逻辑），有 7 条单元测试：
  `cd watch-client; .\gradlew.bat testDebugUnitTest`。

**数据**：`POST /api/message/audio`（流式）+ 设备端 `VoiceActivityRecorder` 分段。

## 6. 习惯建议 · `8:9874`

**目的**：给建议，但绝不擅自把一次行为固化成长期习惯。

**顶栏**：`09:41` · `建议 · 尚未应用`（琥珀）· `68%`
**标题**：`一个小建议`
**胶囊**：`● 确认一次 / 不自动固化`

**主张**：`今天的提案复核，提前 10 分钟?`（大字）

**依据卡**：`近 3 次同类复核均延后完成。建议今天由 14:30 调整至 14:20。`
`置信度 81% · 记忆 3 · 工具 0 · 为什么 ›`

**边界说明**：`仅调整今天，不写成长期习惯。长期规则仍需你另行确认。`
**按钮**：`忽略并留痕`（左）｜`仅今天应用`（右，琥珀）
**页脚**：`未确认前，提醒仍为 14:30`

**规则**：
- 建议必须在"未应用"状态下展示，不可先执行再询问。
- 应用的作用域只有"今天这一次"；写长期规则是另一个流程，需单独确认。
- 忽略后必须留痕，且同一建议在冷却期内不重复出现。
- 建议必须有反例统计（`近 3 次`），没有统计依据的不允许出现。

**数据**：`memories` 中 `layer=ai_candidate, status=candidate` 的候选（见 [MEMORY_MODEL.md](MEMORY_MODEL.md)）。

**目的**：把"哪一环坏了、自动降级成了什么"讲清楚，并且不把失败说成完成。

**顶栏**：`09:40` · `异常 · 外发仍待许可`（红）· `68%`

**主张**：`这次语音没识别成功。请重试或改用文本。`

**降级链卡**（一行一条，用 `→` 连接）：

```
ASR 备用路由也超时 → 文本输入
模型主路由超时 → 轻量模型接替
```

## 9. 低电量极暗模式 · `8:9918`

**目的**：省电，但不牺牲安全。

**顶栏**：`09:41` · `感知已关闭`（琥珀）· `12%`
**标题**：`低电量保护`
**大字**：`12% 需要充电`
**主张**：`持续感知已关闭。需要时，再叫我。`

**说明**：`极暗模式 · 夜间不主动亮屏 语音仅按住时启用，文本仍可用。高风险许可不因省电而跳过。`
**按钮**：`长按语音`（左）｜`文本输入`（右）
**页脚**：`省电情境 · 1380mAh / 扬声器静音`

**规则**：
- 触发阈值：电量 ≤15% 且未充电。恢复：>20% 或开始充电。
- 关闭的是**持续感知**，不是全部能力；长按语音与文本输入必须保留。
- **高风险许可流程完全不变**——这是刻意的，写在文案里。
- 极暗模式只改视觉，不改信息结构与语义色辨识度。

**数据**：`BatteryManager` 本地 + `POST /api/device/{id}/heartbeat`。
