## 2. 事件构成：一个传感器淹没了全部

| 来源 / 类型 | 数量 | 时间跨度 |
| --- | --- | --- |
| `location` / `location_change` | **1345** | 2026-10-03 .. 10-04 |
| `microphone` / `speech` | 171 | 10-04 .. 10-23 |
| `user` / `text` | 82 | 10-02 .. 10-24 |
| `system` / `timer` | 8 | — |
| `notification` | 5 | — |

- 单日事件峰值 1369 条（10-03），其中几乎全是位置更新。
- 11 条记忆里有 **7 条是位置坐标流水**——原始遥测被逐条固化成长期记忆。

**设计影响**：遥测只聚合不落记忆；门控默认先留住，但噪声走 `drop + 回执`。

## 4. 用户到底在问什么

三周内 82 条文字 + 171 条语音，可归为五类：

| 类别 | 典型原话 | 频度 |
| --- | --- | --- |
| **自描述**（我是谁/你能做什么） | 「你是谁」「请你向我介绍你能做的所有功能和你被允许获得的能力」「你被设计是什么」 | **最高**，几乎每次会话都出现 |
| **定时与重复** | 「九点四十提醒我吃早饭」「以后每天 12 点提醒我吃饭」「每天 11:46 推荐今天中午吃什么」 | 高 |
| **学业** | 「求一个期望的最小值」「这个概念怎么推」这类学科提问，以及「今天的作业在第 N 页」 | 高 |
| **社交** | 「定时给家人发一条消息，提醒某件事」 | 中 |
| **回忆/连续性** | 「我刚刚问了你什么问题？你还记得吗」「你现在有什么能力了」 | 高 |

另外有情绪化提问，例如「你觉得我是一个什么样的人？」

**设计影响**：
1. `self.describe` 必须从真实注册表生成——这是被问得最多的问题。
2. `Thread` 必须能回答"刚才聊了什么"，不能依赖上下文窗口。
3. `schedule` Agent 与 `study` Agent 是主战场，不是附加功能。

## 5. 记忆里被明确要求记下的事

`semantic`：一条**用户主动要求写入的敏感话题记忆**（具体内容已脱敏）。
它把某一类话题标记为「需谨慎对待、避免施压」。这里保留的只有**结构**：
用户会主动交给你一条"哪些话题要轻拿轻放"的规则。

`semantic`（产品定位）：*「私人管家……在我做某件需要专注的事情时，
Jarvis 读取屏幕上的要点，在我漏掉时通过手表震动提醒。」*

**设计影响**：敏感话题闸属于策略层；`study` Agent 的目标是"辅助讲课与学习"，
不是"催促完成任务"。

## 6. 任务：真实需求卡在半路

| 任务 | 状态 |
| --- | --- |
| 每日早餐提醒 | done |
| 出门提醒 | done |
| 出门提醒（提前一个半小时） | done |
| 用餐提醒 | **pending** |
| 用餐推荐 | **waiting** |
| 提醒 A | **waiting** |
| 提醒 B | **waiting** |

12 个任务里 4 个没有终态。**设计影响**：Run 状态机 + 恢复 + 失败必须显式报告。

## 8. 用量与 TTS

| 日期 | ASR 秒 | Token |
| --- | --- | --- |
| 10-06 | 442 | 362,804 |
| 10-21 | 844 | 438,897 |
| 10-22 | 0 | 29,190 |
| 10-24 | 0 | 6,920 |

- 高峰日（36 万 / 44 万 Token）明显是开发与压测，不是日常使用；有机使用在 1–3 万/日。
- **`tts_characters` 十天全为 0**，包括 `tts_enabled=1` 的设备在线期间。

**设计影响**：TTS 默认静音，作为可选能力；不要为它付复杂度成本。

```bash
PY
```
