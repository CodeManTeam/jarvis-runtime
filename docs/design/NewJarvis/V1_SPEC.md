## 1. 一句话

v1.0 要回答的不是"Jarvis 还能做什么"，而是**"我凭什么敢把它交给我生活的一部分"**。

答案由草图给出三条：每次介入都要有可核查的依据，每次授权都要有范围和期限，
每次失败都要以失败的样子出现。

## 2. 版本命题

| 维度 | v0.x（现状） | v1.0（本版本） |
| --- | --- | --- |
| 产品心智 | 会聊天、会记日志的助手 | 有边界、可核查的个人自动化中控 |
| 手表 | 单页滚动：配置卡 + 主卡 + 时间线 | 9 个明确状态屏，首页是注意力流 |
| 中控 | 7 项侧栏，偏调试面板 | 5 个平级驾驶舱页，偏决策面板 |
| 权限 | 全局 `trusted_mode` + 5 档 `AutonomyLevel` | 能力 × 范围 × 有效期矩阵，许可单次消费 |
| 解释 | `reason` 一句话 | 四层依据 + 置信度 + 降级链 |
| 记忆 | `content/type/importance` 平铺 | 分层 + 候选态 + 修订 + 忘记 + 销毁 |
| 失败 | toast / 空状态 | 结构化降级屏，保留原错误 |
| 模型 | 单模型 | 主/备路由 + 降级 + 探活恢复 |

## 3. 五条不可妥协（验收红线）

违反任意一条即视为 v1.0 未达标，不允许用"后续优化"绕过。

1. **高风险动作永远逐次确认。** 信任、降级、重试、离线补传、网络恢复，都不得复用或继承一次已消费的许可。
2. **"完成"必须有回执。** 队列接受 ≠ 已送达 ≠ 已执行。失败不得标记为完成，重试成功也必须保留原错误。
3. **许可只覆盖它描述的那一次动作。** 修改正文、换收件人、换附件，旧许可立即失效。
4. **结论必须带证据。** 没有记忆/事件/工具引用的判断，只能显示为"观察"，不能显示为"已完成"。
5. **系统不承诺它做不到的撤销。** 外发后只能追加更正并记录补偿，文案不得出现"全部撤销"。

这五条同时是代码约束和文案约束——UI 上不允许出现做不到的措辞。

## 4. 范围

### 4.1 做

- 手表 9 屏（[WATCH_UI.md](WATCH_UI.md)）：安静待机、注意力流、四层依据、高风险许可、语音输入、习惯建议、离线缓存、服务降级、低电量极暗。
- 中控 5 页（[CONSOLE_UI.md](CONSOLE_UI.md)）：活动流、Agent 编排、记忆库、权限门控、设备与模型。
- 权限模型（[PERMISSION_MODEL.md](PERMISSION_MODEL.md)）：四档矩阵、许可生命周期、受信 Agent 边界、远程配置二次确认。
- 记忆模型（[MEMORY_MODEL.md](MEMORY_MODEL.md)）：四层、候选态、修订、忘记、导出、销毁。
- 活动与依据（[ACTIVITY_EVIDENCE.md](ACTIVITY_EVIDENCE.md)）：注意力四分类、四层证据、置信度、降级描述。
- 设备与模型运维（[DEVICE_OPS.md](DEVICE_OPS.md)）：指标口径、路由降级、远程配置、APK 升级与回滚、自迭代沙箱、RCE 白名单。

### 4.2 不做

- 多用户、协作、团队空间（草图明确写"单人工作空间/无协作权限"）。
- 水平扩展、多实例一致性。
- 离线智能：离线只缓存提示与通知，**不执行工具、不重放外发**。
- 开机自启、被杀自动复活。
- 无确认的批量外发。
- "撤销已完成的外部动作"这类做不到的承诺。

### 4.3 只设计不承诺

## 6. 五条端到端验收场景

1. **许可只此一次**：手表发出"把提案发给林工" → 生成待发 + 许可卡 → 许可后发送 → 二次发送必须重新许可；期间修改正文则原许可自动失效。
2. **失败不冒充完成**：ASR 两路超时 → 手表显示降级屏并保留文本通道 → 中控记录完整错误与重试链 → 任何界面都不出现"已完成"。
3. **证据可溯源**：任取一条"已添加 14:30 提醒"，能点开四层依据，逐条打开引用的记忆/事件/工具回执。
4. **离线不越权**：断网期间缓存通知，恢复后按事件 ID 去重补传；离线期间产生的外发意图仍停在"待许可"。
5. **忘记有边界**：忘记一条长期记忆后，检索不再命中，但历史活动里对该记忆的引用仍可打开（标记为已忘记），已发送的外部消息不受影响。

## 7. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 权限矩阵粒度失控 | 配置复杂到没人懂 | 首版只开 5–8 条能力，其余走默认档；矩阵必须有"恢复默认" |
| 四层依据导致数据膨胀 | 存储与渲染成本上升 | 证据只存引用 ID，正文按需取；列表页只带计数不带正文 |
| 深色 + 低亮度下中文可读性 | 实机字体发虚 | 真机实测后再定字重；正文不低于 12，禁用 300 字重做正文 |
| 400×540 与 360×480 换算 | 布局挤或字过小 | 见 [DESIGN_SYSTEM_V2.md](DESIGN_SYSTEM_V2.md) 的缩放规则：布局缩、字号不缩 |
| 自迭代/RCE 的界面先于能力 | 用户以为可用 | 相关界面默认折叠并显式标注"未接入" |
| 全量销毁不可恢复 | 数据事故 | 强制导出校验 + 二次输入 + 7 天备份窗，且列为最高风险 |

四个开放问题已全部决策，详见 [DECISIONS.md](DECISIONS.md)：

1. **记忆迁移**：`episodic→short`、`fact/preference→long`（D1）。
2. **对话入口**：并入活动流的"直接回复"，删除独立 chat 视图；导航保持 5 个平级 tab，
   只增加一个全局"待许可悬浮条"（D2）。
3. **`trusted_mode`**：删除全局布尔，改为主 Agent 持有的一条显式受信 grant，可查看可撤销，
   高风险能力永不覆盖（D3）。
4. **全量销毁**：纳入 v1.0，按最高风险操作实施（D4）。
